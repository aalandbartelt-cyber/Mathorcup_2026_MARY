## 2. 练习题 1：观影大数据分析

### 2.1 题意拆解（题面 P1）

> 终极问题：电影票房的影响因素有哪些？
> 分维度分析：观众喜欢什么类型/主题关键词？电影风格随时间如何变化？预算高低是否影响票房？高票房/高评分导演有哪些？发行时间选在何时？拍原创好还是改编好？

- **问题（1）**：用 `tmdb_5000_movies.csv` + `tmdb_5000_credits.csv` 做数据清洗、挖掘、分析、可视化，研究票房影响因素，从不同维度分析讨论。
- **问题（2）**：`tmdb_1000_predict.csv` 含 1000 部电影基本信息，选合适指标做特征提取、建机器学习预测模型，预测 `vote_average` 和 `vote_count`，保存为 `tmdb_1000_predicted.csv`。

**注意措辞**：Q1 要的是“影响因素”（解释性分析），Q2 要的是“预测”（泛化性能）。两者方法不同：Q1 重统计描述与相关性，Q2 重交叉验证与泛化。

### 2.2 数据体检（实测，2026-10-21）

**三个文件的真实规模**

| 文件 | 形状 | 说明 |
|---|---|---|
| `tmdb_5000_movies.csv` | **4803 × 20** | 并非题面所说的“近 5000 部”，实际 4803 条；含 budget/revenue/popularity/runtime/vote_* 等 |
| `tmdb_5000_credits.csv` | **4803 × 4** | movie_id、title、cast、crew 四个字段（cast/crew 为 JSON 字符串） |
| `tmdb_1000_predict.csv` | **1000 × 20** | 与 movies 同列结构，`vote_average`、`vote_count` 两列**全为空**（待预测） |

**movies 缺失情况（按缺失量排序）**

| 字段 | 缺失数 | 占比 | 处理建议 |
|---|---|---|---|
| homepage | 3091 | 64.4% | 直接删除该列（对预测无价值） |
| tagline | 844 | 17.6% | 删除或填“无” |
| overview | 3 | 0.06% | 删除该列或填“无” |
| runtime | 2 | 0.04% | 按官方教程上网补全或用中位数 |
| release_date | 1 | 0.02% | 按官方教程补全（见 §2.3） |

**目标变量分布（决定建模策略）**

| 变量 | 均值 | 标准差 | 最小 | 中位数 | 75% | 最大 | 零值占比 |
|---|---|---|---|---|---|---|---|
| vote_average | 6.09 | 1.19 | 0 | 6.2 | 6.8 | 10 | 1.3% |
| vote_count | 690.2 | 1234.6 | 0 | 235 | 737 | 13752 | 1.3% |

- `vote_count` 严重右偏（均值≈3 倍中位数），**必须做 log1p 变换**再回归，否则模型被少数大片主导。
- `vote_average` 近似正态（mean 6.09/std 1.19），可直接回归，但注意 0 分样本（63 条）是“无人评分”，应剔除而不是当真实评分。

**其他零值（直接影响筛选口径）**

| 字段 | 零值数 | 占比 | 说明 |
|---|---|---|---|
| budget | 1037 | 21.6% | 预算未知，不能当 0 计算 ROI |
| revenue | 1427 | 29.7% | 票房未知，不能当 0 |
| popularity | 1 | 0.02% | 可忽略但按教程应剔除 |
| vote_average / vote_count | 63 / 62 | 1.3% | 无人评分，应剔除 |

**其他数据事实**
- `release_date` 范围 1916-09-04 → 2017-02-03（时间跨度大，注意早期电影票房/评分口径差异）。
- `genres` 共 **20 个唯一类型**，Top：Drama 2297、Comedy 1722、Thriller 1274、Action 1154、Romance 894、Adventure 790、Crime 696、Science Fiction 535。
- `keywords` 共 **9813 个唯一关键词、36194 次出现**；`cast`/`crew` 每部电影数十人。
- 每行 `genres/keywords/production_companies/production_countries/spoken_languages` 都是 JSON 字符串，需展开。

### 2.3 官方教程就是标准作业流程（含填空题复算答案）

题面 P2–P9 是**填空式教程**，把“清洗 7 步 + 5W1H 分析”固定下来。按这个顺序做，等于按官方预期写论文。

**数据清洗 7 步（教程原文结构）**

| 步骤 | 官方要求 | 复算答案（基于实测数据） |
|---|---|---|
| 1 导入数据 | 读入两份 CSV | 4803 行 × 20 列（movies）/ × 4 列（credits） |
| 2 缺失值处理 | “缺失记录仅\_\_条，采取网上搜索补全” | **release_date 缺 1 条**：电影《America Is Still the Place》；**runtime 缺 2 条**：《Chiamatemi Francesco - Il Papa della gente》《To Be Frank, Sinatra at 100》 |
| 3 重复值处理 | 统计不重复 id | **4803 个不重复 id = 总行数 4803**，无重复 |
| 4 日期值处理 | release_date 转日期类型 | 用 `pd.to_datetime(errors="coerce")`，1916→2017 |
| 5 筛选数据 | 票房、预算、受欢迎程度、评分为 \_\_\_ 的数据去除；评分人数大于 \_\_\_ | 零值口径：**去掉 budget==0（1037）、revenue==0（1427）、popularity==0（1）、vote_average==0（63）**；评分人数阈值自定，示例 `vote_count>=50` → **保留 2961 行、20 字段**（阈值 10 → 3186 行；100 → 2715 行） |
| 6 json 数据转换 | genres/keywords/production_companies/production_countries/cast/crew 六列 JSON → 列表/字符串 | `json.loads` → `explode`；cast/crew 取 Top-N 名字做 multi-hot |
| 7 数据备份 | 保存清洗后数据 | 建议保存 `movies_clean.csv` 并记录行数，便于复现 |

> 教程里“缺失记录仅 \_\_\_ 条”与电影名/runtime 三个空，用上表答案即可填对（这正是官方留的“标准答案”）。

**数据分析 5W1H 框架（教程原文，P4–P9）**

| 维度 | 官方要求回答的问题 | 指定图表 | 数据落点建议 |
|---|---|---|---|
| Why | 为什么研究票房影响因素 | 无 | 引言/问题分析 |
| What | 观众喜欢什么类型/主题 | 类型数量**条形图**、类型占比**饼图**、类型变化**折线图**、类型预算/利润**组合图**、关键词**词云** | genres 展开计数；按年统计；keywords 词云（可加词频表） |
| When | 电影时长与发行时间 | runtime **直方图**、每月电影数量与单片平均票房（双轴） | release_date → 年/月/季；runtime 分箱 |
| Where | 制作公司/国家 | 本题设定不作分析（教程注明） | 可作扩展：国家票房差异 |
| Who | 高票房/高评分导演 | 票房分布、Top10 导演；评分分布、Top10 导演 | credits.crew 里 job=="Director" 解析 |
| How | 原创 vs 改编 | 占比**饼图**、预算/利润率**组合图** | 用 keywords 是否含 "based on novel" 等判定，或对比 title 与 original_title |
| How much | 量化票房影响因素 | **相关系数矩阵**、影响因素**散点图** | budget/revenue/popularity/runtime/vote_count 相关矩阵 + 散点 |

**这张表就是 Q1 论文的“分析章节大纲”**——每个维度对应一个小节 + 1–2 张图 + 2–3 句结论。照做即可覆盖官方期待。

### 2.4 Q1 执行方案（可直接跑）

1. **清洗**：按 §2.3 七步执行，输出 `movies_clean.csv` 并记录每一步行数变化（写进论文“数据预处理”表）。
2. **类型/关键词特征**：`genres` 做 multi-hot（20 维）；`keywords` 取 Top-100 做 multi-hot 或统计关键词数量；输出“类型 × 平均票房/评分”表。
3. **时间维度**：按发行年份统计“平均票房/影片数/平均评分”，标注关键年段；按月份统计“上映数量与平均票房”（教程指定）。
4. **人物维度**：从 `crew` 解析导演，统计 Top10 票房/评分导演；从 `cast` 解析演员，可做“演员票房号召力”辅助分析。
5. **量化关系**：相关性矩阵（Pearson + Spearman，票房右偏用 Spearman 更稳）；分预算档位看票房中位数（避免均值被大片拉高）；对“类型/国家/语言”做分组检验（Kruskal-Wallis 或方差分析）。
6. **结论写法**：每个维度一段“现象+数字+解释”，例如“Drama 数量最多（2297 部）但平均票房并非最高，说明类型数量与商业回报不呈正相关”。

### 2.5 Q2 预测方案（1000 部电影双目标）

**特征工程清单**

| 类别 | 做法 |
|---|---|
| JSON 多标签 | genres 20 维 multi-hot；keywords Top-100 multi-hot；production_companies/countries Top-50；cast/crew 取 Top-N 及人数统计 |
| 数值 | budget、popularity、runtime；budget 可 log1p；缺失用中位数 |
| 日期 | release_year、month、quarter、影片年龄（2017−year）、是否暑期档/圣诞档 |
| 类别 | original_language（频数编码/Target 编码）、status |
| 文本（可选） | overview/tagline 的 TF-IDF + SVD（可选加分，非必需） |
| 统计聚合 | 导演历史作品数/平均票房、演员数量、公司数量（需注意只用训练集统计，防泄漏） |

**建模路线（由易到难）**

1. **Baseline**：`vote_average` 用 Ridge 回归；`vote_count` 先 `log1p` 再 Ridge。报告 R²/RMSE。
2. **主模型**：RandomForest / XGBoost / LightGBM 三个对比；`vote_count` 在 log 空间训练，预测后 `expm1` 还原。
3. **验证**：5 折交叉验证（KFlod + shuffle），分别报告两目标指标；按 `vote_count` 分档看误差（少量评分电影更难预测）。
4. **特征重要性**：输出 Top-15 特征，写进论文（对应 Q1 的“影响因素”结论闭环）。
5. **输出**：1000 行 × 原 20 列 + 填入预测的两列 → `tmdb_1000_predicted.csv`（列顺序与输入保持一致，避免评分脚本读错）。

**防泄漏红线**
- 预测 `vote_count` 时**不能用 `vote_average`**（另一个目标）；预测 `vote_average` 时也不能用 `vote_count`。
- `revenue` 是上映后结果，用作特征会引入未来信息，建议**不作为预测特征**（或在论文中说明其不可得性）。
- 目标编码（Target Encoding）必须用折内统计，否则泄漏。

**指标建议**：`vote_average` 报 R²/RMSE/MAE；`vote_count` 报 log 空间 RMSE 与还原后的 MAPE（长尾目标只看 R² 会失真）。

### 2.6 代码骨架（pandas + sklearn，约 60 行）

```python
import json, numpy as np, pandas as pd
from sklearn.model_selection import KFold
from sklearn.ensemble import RandomForestRegressor
from sklearn.metrics import r2_score, mean_squared_error

# 1) 读取与基础清洗
m = pd.read_csv("data/tmdb_5000_movies.csv")
m["release_date"] = pd.to_datetime(m["release_date"], errors="coerce")
m = m[(m.budget > 0) & (m.revenue > 0) & (m.popularity > 0) & (m.vote_average > 0)]

# 2) JSON 展开：genres multi-hot
genres = m["genres"].apply(lambda s: [g["name"] for g in json.loads(s)])
all_genres = sorted({g for gs in genres for g in gs})
for g in all_genres:
    m[f"genre_{g}"] = genres.apply(lambda gs, g=g: int(g in gs))

# 3) 日期与数值特征
m["year"] = m["release_date"].dt.year
m["month"] = m["release_date"].dt.month
m["budget_log"] = np.log1p(m["budget"])
m["runtime"] = m["runtime"].fillna(m["runtime"].median())
feat_cols = ["budget_log", "popularity", "runtime", "year", "month"] + [f"genre_{g}" for g in all_genres]

# 4) 双目标 + 5 折验证
X = m[feat_cols].values
y_avg = m["vote_average"].values
y_cnt = np.log1p(m["vote_count"].values)
for name, y in [("vote_average", y_avg), ("vote_count_log", y_cnt)]:
    scores = []
    for tr, va in KFold(5, shuffle=True, random_state=42).split(X):
        rf = RandomForestRegressor(n_estimators=300, random_state=42, n_jobs=-1)
        rf.fit(X[tr], y[tr]); pred = rf.predict(X[va])
        scores.append(r2_score(y[va], pred))
    print(name, "5-fold R2: %.3f ± %.3f" % (np.mean(scores), np.std(scores)))

# 5) 对 1000 部预测
p = pd.read_csv("data/tmdb_1000_predict.csv")
# （对 p 做与 m 完全一致的特征工程后，用全量 m 训练的模型预测）
```

### 2.7 常见坑（练习 1）

1. **把 0 当真实值**：budget/revenue 的 0 是“未知”，直接参与计算会把 ROI 拉爆。
2. **vote_count 不取对数**：模型会被《阿凡达》这类 1.3 万评分的片子主导。
3. **JSON 直接当字符串用**：必须 `json.loads` 后展开，否则类型/关键词信息全丢。
4. **训练/预测特征列不一致**：以 `tmdb_1000_predict.csv` 的列为准做交集，避免某一列在预测集缺失导致报错。
5. **忽略时间漂移**：1916–2017 跨百年，票房未通胀调整；至少加“年份/年代”特征或在论文中说明。
6. **导演/演员聚合泄漏**：用“全量数据”统计导演平均票房再喂给模型 = 泄漏；应折内统计。

## 3. 练习题 2：新冠肺炎 CT 图像识别

### 3.1 题意拆解（题面 P1）

- 背景：RT-PCR 需 4–6 小时且试剂短缺，CT 影像有望快速筛查；给出 6 个典型 CT 征象（GGO、多发外周带 GGO、铺路石征、斑片状 GGO 伴实变、弥漫性 GGO 伴支气管充气征、大面积实变伴小叶间质增厚）及影响图像质量的因素（空间/密度分辨力、噪声、伪影）。
- **问题（1）**：用 `CT_COVID` 与 `CT_NonCOVID` 两个文件夹的数据训练与测试，建立模型并**检验识别准确性**。
- **问题（2）**：对 `predict` 文件夹中的 **577 张** CT 图像预测是否感染，写出预测结果。

### 3.2 数据体检（实测，2026-10-21）

| 文件夹 | 实际数量 | 格式 | 说明 |
|---|---|---|---|
| CT_COVID | **349** | 全部 PNG | 文件名多为论文截图式命名，**含 `%0`、`%1` 等 URL 编码字符（217 个文件）** |
| CT_NonCOVID | **397** | **202 JPG + 195 PNG** | 文件名多为数字编号（如 102.png） |
| predict | **577** | **410 PNG + 167 JPG**（另有 1 个 .DS_Store 需忽略） | 命名统一 `Predict_00001.png`… |
| 合计训练 | **746** | 混合 | 类别比例 349 : 397 ≈ **46.8% : 53.2%（基本均衡）** |

**图像属性**
- 尺寸差异极大：抽样可见 172×124、287×202、348×253、512×340、512×512 等，**必须统一 resize**。
- 颜色模式混合：**RGBA（带透明通道）/ RGB / L（灰度）** 三种都有 → 必须 `convert("RGB")`，否则 RGBA 读入会变 4 通道导致模型报错。
- 数据量小（746 张训练 + 577 张预测），**过拟合风险高**，交叉验证与增强是必选项。
- **潜在数据泄漏点**：CT_COVID 文件名有同前缀多帧（如 `...p3-89%0.png`、`...p3-89%1.png` 很可能是同一病例的不同切片/版本）。随机划分会把同一病例分到训练和验证两侧，导致验证分数虚高。**建议按文件名前缀分组划分（GroupKFold）**。

### 3.3 方案 A：迁移学习分类（推荐，torchvision）

**流程**：转 RGB → resize 224/256 → 可选 CLAHE 增强 → 归一化 → 冻结骨干训练分类头 → 解冻微调 → 5 折（按前缀分组）→ 评估 → 对 577 张推理。

**模型选择**：ResNet50、DenseNet-121、EfficientNet-B0 三个对比（2023 优秀论文在坑洼题中用 DenseNet-121 取得 99.34%，可作为对标）[见主文档 P23-2]。

**训练配置建议**

| 项 | 建议值 |
|---|---|
| 输入尺寸 | 224×224（或 256） |
| 归一化 | ImageNet mean/std |
| 数据增强 | 随机水平翻转、±10° 旋转、亮度/对比度 0.2、随机擦除 p=0.2（医学图像慎用垂直翻转） |
| 损失 | 交叉熵；类别基本均衡，可不用加权 |
| 优化器 | AdamW，lr=1e-4（微调阶段 1e-5），余弦退火，早停 patience=8 |
| 批次 | 16–32（12GB 显存足够） |
| 轮数 | 冻结 15 轮 + 微调 30 轮 |

### 3.4 方案 B：ultralytics 分类（最省事）

把数据整理成 ultralytics 分类目录：

```
cls_dataset/
├── train/{COVID,NonCOVID}   # 按前缀分组后的训练集
└── val/{COVID,NonCOVID}
```

```bash
yolo classify train model=weights/yolo26n-cls.pt data=cls_dataset imgsz=224 epochs=60 batch=32 device=0
yolo classify predict model=runs/classify/train/weights/best.pt source=predict_dir save_txt=True
```

优点：一条命令出结果、自带增强与日志；缺点：可解释性与自定义空间不如 torchvision。两个方案都建议跑一遍做对比（论文里就是“模型对比实验”）。

### 3.5 评估设计（对应 Q1“检验准确性”）

1. **基础指标**：Accuracy、Precision、Recall、F1、AUC，混淆矩阵（原始+归一化）。
2. **5 折交叉验证**：报告均值±标准差，而不是单次划分的“好看数字”。
3. **按前缀分组验证**：与随机划分对比，若差距大，说明存在同病例泄漏——这个对比本身就是论文亮点。
4. **鲁棒性**：加高斯噪声/亮度扰动，看 F1 保持率（可参考 2025-3 的 ±30% 亮度测试）。
5. **医学场景侧重**：漏诊（FN）代价高于误诊，报告 Recall 与“严重病例漏检率”。
6. **可解释性（加分）**：Grad-CAM 热力图，看模型关注区域是否落在肺野而非扫描伪影/文字标注。

### 3.7 代码骨架（torchvision，约 50 行）

```python
from pathlib import Path
from PIL import Image
import torch
from torch.utils.data import Dataset, DataLoader
from torchvision import transforms, models

class CTDataset(Dataset):
    def __init__(self, root, tf):
        self.items = []
        for label, sub in [(0, "CT_NonCOVID"), (1, "CT_COVID")]:
            for p in (Path(root) / sub).iterdir():
                if p.suffix.lower() in {".png", ".jpg", ".jpeg"}:
                    self.items.append((p, label))
        self.tf = tf
    def __len__(self): return len(self.items)
    def __getitem__(self, i):
        p, y = self.items[i]
        img = Image.open(p).convert("RGB")      # 关键：RGBA/L → RGB
        return self.tf(img), torch.tensor(y)

tf_train = transforms.Compose([
    transforms.Resize((224, 224)),
    transforms.RandomHorizontalFlip(),
    transforms.RandomRotation(10),
    transforms.ColorJitter(0.2, 0.2),
    transforms.ToTensor(),
    transforms.Normalize([0.485, 0.456, 0.406], [0.229, 0.224, 0.225]),
])
model = models.resnet50(weights=models.ResNet50_Weights.IMAGENET1K_V2)
model.fc = torch.nn.Linear(model.fc.in_features, 2)
# 冻结骨干 → 训练头 → 解冻微调；5 折按文件名前缀分组（GroupKFold）
```

### 3.8 常见坑（练习 2）

1. **RGBA/L 模式**：不 `convert("RGB")` 会在 batch 拼接时报通道数错误。
2. **尺寸不一**：同一 batch 必须同尺寸，必须 resize/collate 补齐。
3. **文件名特殊字符**：CT_COVID 有 217 个含 `%0/%1` 的文件，用 `pathlib` 处理、避免 shell 转义；写 CSV 时原样保留文件名。
4. **同病例多帧泄漏**：按文件名前缀分组划分（GroupKFold），并在论文中报告“随机划分 vs 分组划分”的差异。
5. **小样本过拟合**：746 张训练图，必须交叉验证 + 强增强 + 早停；不要报单次 8:2 的“99%”。
6. **类别其实均衡**（46.8/53.2）：不要盲目 SMOTE；重点在泛化。
7. **`.DS_Store`**：predict 目录里有 macOS 垃圾文件，读目录时要过滤非图片后缀。
