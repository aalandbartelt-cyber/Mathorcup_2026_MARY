# 论文文档与图表交付规范

本文件记录用户已明确的长期交付要求，适用于三问及后续总论文。

1. 每次生成或修改论文Word，必须同步导出对应PDF，并生成带书签的审计合订本。当前仅第一问具备完整Word时，合订本包含第一问正文、独立假设和问题分析；其他问成熟后按实际文档并入，不补造章节或结果。
2. 模板直接复制副本后替换内容。标题和正文必须同时继承原段落属性与文字的直接格式，不能仅沿用样式名；样式文件和页面设置应与原件对账。总论文组装时再按官方要求统一纸张、版心和页码。
3. 公式必须为Word原生结构化OMML，使用真正的分式、上下标、求和与重音，不用图片、伪上下标或线性字符串。公式在一行三列表中，第三列连续编号。
4. 表题在表上方，图题在图下方，每张图和每张表均在正文引用。图文件内部不写整图图题，不用灰色分面底框；面板标识、轴标题与重点信息清晰，数字和图例不得遮挡数据。
5. 出图使用R/ggplot2与theme_mcup，300dpi，中文呈现，专有名词保留英文。参考论文仅吸收适合论证任务的视觉表达，不为装饰增加图数。图例的形状、填充和颜色必须与图中实际编码一致。
6. 论文只使用学术方法名称；实验编号、内部参考代号和选择管理语言仅保存在内部记录。交付前扫描Word全部文本及属性、PDF、图中文字源、图清单、附录、程序、文件名和ZIP内容。
7. 新版本保留独立文件；旧稿保存到当前交付目录以外的历史归档。所有正文数字均由本队已审计结果支持；重复指标均值与平均折外预测严格区分，不利结果如实报告。
8. 不再生成或排版源程序附录Word/PDF。打包时仅准备附录核心代码和简短说明，由论文手编排；完整复现程序继续放支撑材料。此项为用户2026-10-25最新要求，优先于以往“附录全代码”的工作分配。

同步导出命令：`python scripts/export_paper_review.py --question Q1_感官评分`。
打包命令：`python scripts/package_paper_handoff.py --question Q1_感官评分`。
