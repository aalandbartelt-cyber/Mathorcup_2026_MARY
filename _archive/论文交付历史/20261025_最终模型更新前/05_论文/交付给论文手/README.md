# 交付给论文手

> 每个问题一个子文件夹；打包后的 zip 直接放本目录，文件名 `<问题>_交付包.zip`。

## 交付包必须包含

以 Q1 为例（`Q1_感官评分/`）：

| 内容 | 文件 | 要求 |
|---|---|---|
| 论文正文 | `第一问_论文正文_v1.docx` | 套用 `第一问_论文正文_最终版.docx` 的版式：Heading 1/2/3、Body Text、公式 1×3 表（第三列编号）、图题在下、表题在上 |
| 模型假设 | `模型假设_Q1.docx` | 对标 `定稿.docx`“模型假设”：一句引导 + 假设1…n，每条写数据依据与放宽后的影响 |
| 问题分析 | `问题分析_Q1.docx` | 对标 `定稿.docx`“2.1 问题一分析”：任务本质 → 2–3 条难点 → 对策，1–2 段 |
| 图片源文件 | `图片/`（含 `图片/附图/`） | 300dpi PNG + 有则附 PDF/SVG；文件名与正文图号一致；附图单独放 |
| 交付说明 | `交付说明.md` | 版本、HEAD、清单、待确认项（由打包脚本生成） |

## 打包

```bash
python scripts/package_paper_handoff.py --question Q1_感官评分
# → 05_论文/交付给论文手/Q1_感官评分_交付包.zip
```

脚本会检查：正文 docx、模型假设、问题分析、至少一张图；缺项会报错。

## 规则

- 图必须先经用户检查质量，确认后再进正文 docx 和交付包。
- 数字与 `03_结果/<Q>/` 的指标文件一致；正文 docx 的版本号在交付说明里登记。
- 每次更新交付包，版本号 +1（v1、v2…），旧包保留在 `_历史/`。
