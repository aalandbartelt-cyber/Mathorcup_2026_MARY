# 自强平台操作指南（MathorCup 实战版）

> 来源：2026-09-11「挑战杯擂台赛 / Go2 强化学习」项目在自强平台（自强 5000）的真实使用记录（Codex 对话 thread `01a08e56-c11a-7b91-8f82-310bd5f69b1b`）。
> 适用范围：上海大学自强平台 GPU 容器（Jupyter 网页终端 + 云盘持久盘），MathorCup 训练/评测同样适用。
> 原则：**平台只做训练与重计算；代码用 git/patch 进出；结果打包回本地；用完立即销毁容器。**

---

## 1. 平台与容器基础

### 1.1 你拿到的是什么

- 一个 **Jupyter 网页终端**容器，用户名 `jovyan`，容器名形如：
  `shu-common-24120620-notebook-hk0epq-0`
- 每次新建/重建容器，**容器名会变**（记录里出现过 hk0epq / nuxxz5 / f2fe6k / 7ku889）。
- 常见 GPU 规格：**2×A100-PCIE-40GB**（也有 4 卡规格，按需申请）；驱动 535 / CUDA 12.x。
- 系统自带 conda 在 `/opt/conda`；自建环境建议放 `~/conda/envs/<name>`。

### 1.2 什么会丢、什么不会丢

| 路径 | 生命周期 | 用途 |
|---|---|---|
| `/tmp`、容器内系统目录 | **容器销毁即丢** | 临时文件 |
| `~/`（云盘持久盘） | **保留** | 代码、环境、训练输出、结果 |
| `~/conda/envs/*` | 保留 | 自建 conda 环境 |
| `~/go2_work`（示例） | 保留 | 项目工作目录、日志、结果 |

**结论**：环境、数据、代码、结果全部放 `~` 下；`/tmp` 只放一次性补丁/临时脚本。

### 1.3 计费

- **按 GPU 卡时计费**，双卡容器双倍计费；空转也在烧钱。
- GPU 任务一结束就**打包结果 → 销毁容器**；CPU 分析、画图、写论文全部回本地做。
- 记录里的教训：双卡容器挂起期间用户专门提醒“正在计费”；后来每次评测完都先停容器再写代码。

## 2. 进入容器后的第一组命令

```bash
# 1) 激活环境（绝对路径最稳）
source /opt/conda/etc/profile.d/conda.sh
conda activate /home/jovyan/conda/envs/<你的环境>
export LD_LIBRARY_PATH="$CONDA_PREFIX/lib:${LD_LIBRARY_PATH:-}"

# 2) 看卡
nvidia-smi --query-gpu=index,name,driver_version,memory.total --format=csv,noheader

# 3) 逐卡自检（关键！）
for i in $(seq 0 $(( $(nvidia-smi -L | wc -l) - 1 ))); do
  echo "== GPU $i =="
  CUDA_VISIBLE_DEVICES=$i timeout 60 python -c "
import torch
print('cuda', torch.cuda.is_available(), 'count', torch.cuda.device_count())
print(torch.cuda.get_device_name(0))
x=torch.randn(1024,1024,device='cuda'); print((x@x).sum().item())
"
  echo "exit=$?"
done
```

`LD_LIBRARY_PATH` 让 conda 的库优先——这对训练有利，但会**带坏系统工具**（见 §5.2）。

## 3. GPU 分配：最容易踩的坑

### 3.1 真实事故

同一账号连续两次申请 **2×A100 容器**，都只有一张卡可用：

| 容器 | GPU 0 | GPU 1 |
|---|---|---|
| 第 1 个双卡容器 | PyTorch 正常 | CUDA 上下文初始化失败 |
| 第 2 个双卡容器 | 测试超时（exit 124） | 正常 |

结论：**这是平台/容器分配问题，不是代码问题**。`nvidia-smi` 能枚举 ≠ 能建 CUDA 上下文。
最终改为**单卡容器**，评测稳定跑完（9/9 任务、63 份结果）。

### 3.2 正确做法

1. 每次开机先跑 §2 的**逐卡自检**；任何一张卡 `torch.cuda.is_available()` 失败或超时，**不要启动正式任务**。
2. 双卡不可用时，直接换单卡容器，别在网络/驱动上耗时间。
3. 多卡并行 = **每卡一个独立进程**（`CUDA_VISIBLE_DEVICES=0/1/...`），不要在这个数据规模上做 DDP。
4. `nvidia-smi` 里的 PID 与容器内 PID 不一致是正常的宿主/容器映射，不是异常。

### 3.3 MathorCup 的选型建议

- 数据集通常几百 MB 到几 GB、单实验 20–40 分钟：**单卡 A100 足够**。
- 要并行消融时，申请多卡但**每卡独立跑一个配置**；用脚本按 `CUDA_VISIBLE_DEVICES` 分配。
- 本地 5070 Ti 负责调试与出图；平台只跑正式训练/批量评测。

## 4. 代码与数据怎么进出

### 4.1 首选：git

```bash
cd ~/go2_work/<repo>
timeout 30 env -u LD_LIBRARY_PATH GIT_TERMINAL_PROMPT=0 git pull --ff-only
git rev-parse --short HEAD
```

### 4.2 平台网络故障：GitHub 域名解析失败

记录中的真实症状：

```
fatal: unable to access 'https://github.com/...': Could not resolve host: github.com
```

排查顺序（都做过）：

1. `getent hosts github.com` / `curl -I https://github.com` —— 判断是 DNS 还是出口。
2. `curl --resolve github.com:443:<IP> https://github.com` —— **直接绑 IP 能通，说明出口正常、DNS 坏了**。
3. `git config http.curloptResolve` —— 容器 Git 是 **2.25.1**，不支持该配置。
4. 写 `/etc/hosts` —— **无 sudo/无权限**。
5. 用户态 DNS 映射 / 临时本地代理 —— 能通但复杂，作为最后手段。

### 4.3 最可靠的兜底：patch 文件

平台 DNS 坏时，**不要在容器里修网络**，改走“本地生成补丁 → 平台 apply”：

```powershell
# Windows 本地（能访问 GitHub）
curl.exe -sSL "https://github.com/<user>/<repo>/compare/<base>...<head>.patch" -o sync.patch
```

把 `sync.patch` 传到容器（云盘/Jupyter 上传），然后：

```bash
cd ~/go2_work/<repo>
git am --committer-date-is-author-date /path/to/sync.patch
git rev-parse HEAD          # 必须等于本地 head
git status --short          # 应为空
```

记录里用这个方法把 9 个提交从 `d222dcb` 精确重建为 `b241199`（commit 与 tree 哈希一致）。
**要点**：先在本地演练一遍 `git am`，确认哈希一致，再在计费容器里执行。

### 4.4 数据

- 大数据（数据集、权重）走**云盘上传**，放 `~/` 持久盘；不要放 `/tmp`。
- 结果回传：`tar -czf` 打包 + `sha256sum` 清单，下载到本地再解压。

```bash
cd ~/go2_work
tar -czf results_$(date +%Y%m%d).tar.gz <结果目录>
sha256sum results_*.tar.gz > results_$(date +%Y%m%d).sha256
```

## 5. 长任务：保活、监控、恢复

### 5.1 启动方式

- 不要依赖网页终端会话：用 `nohup` / `setsid` 后台启动，写 **pid 文件**与日志。
- 启动器要可**断点恢复**：输出目录带 manifest、每个任务一个标记文件（`WORKER_0_PASS`、`MATRIX_FAILED`、`FORMAL_MATRIX_PASS`）。
- 一次启动后，监控只读状态，不重启。

### 5.2 不要用 `watch`

记录中的坑：`watch` 在 conda 环境下**段错误**——`LD_LIBRARY_PATH` 让 `watch` 误加载 conda 的 `libncursesw/libtinfo`。

```bash
# 错误：直接 watch
watch -n 15 'tail -n 50 eval.log'

# 正确：剥掉 LD_LIBRARY_PATH
env -u LD_LIBRARY_PATH /usr/bin/watch -n 15 'tail -n 50 eval.log'
```

更稳的是写一个**只读状态脚本**：打印 PID、完成数、失败标记、日志尾部；不轮询、不写文件、不杀进程。

### 5.3 判断“卡住”还是“在跑”

| 现象 | 判断方法 |
|---|---|
| 终端无输出 | 看 pid 是否存在、`ps -o pid,etime,%cpu,cmd -p <pid>` |
| `jobs_complete=0/9` 很久 | 正常：一个任务要跑完 7 个地形才 +1 |
| `nvidia-smi` 有显存占用 | 任务在跑 |
| 日志出现 `Traceback`/`MATRIX_FAILED` | 真失败，按日志修 |
| `watch` 段错误 | 只是监控工具崩了，任务通常没事 |

### 5.4 完成判据（示例）

```text
jobs_complete=9/9
worker=WORKER_0_PASS present
MATRIX_FAILED absent
FORMAL_MATRIX_PASS present
```

出现全部 PASS 再打包、销毁容器。

## 6. 常见报错速查

| 报错 | 原因 | 处理 |
|---|---|---|
| `libX11.so.6: cannot open shared object file` | 无头容器缺 X11，IsaacGym 可选插件加载失败 | **可忽略**（不影响训练/评测）；确需可 `apt-get install -y libx11-6`（无 sudo 则忽略） |
| `watch: segmentation fault` | conda `LD_LIBRARY_PATH` 污染系统工具 | `env -u LD_LIBRARY_PATH /usr/bin/watch ...` |
| `bash: $'\r': command not found` | Windows 检出把 `.sh` 转成 CRLF | `.gitattributes` 加 `*.sh text eol=lf`；`git checkout-index --force -- <脚本>`；`bash -n` 复验 |
| `Could not resolve host: github.com` | 容器 DNS 故障（出口正常） | §4.2/§4.3：绑 IP 验证、patch 兜底 |
| `git pull` 长时间无响应 | 网络挂起 | `timeout 30 env -u LD_LIBRARY_PATH GIT_TERMINAL_PROMPT=0 git pull --ff-only` |
| 一张卡 `cuda.is_available()` False / 超时 | 平台 GPU 分配异常 | 换单卡容器，不要修代码 |
| `nvidia-smi` PID 与容器内不一致 | 宿主/容器 PID 映射 | 正常，不影响 |
| 磁盘满 | 输出/缓存写满系统盘 | 输出到 `~/`，清 `~/.cache`、`/tmp` |

## 8. MathorCup 专用流程（结合本仓库）

1. 本地把代码推到 GitHub（`aalandbartelt-cyber/Mathorcup_2026_MARY`）。
2. 平台新建 GPU 容器 → 逐卡自检 → `git clone/pull` 或 patch 同步。
3. 数据通过云盘上传到 `~/mathorcup_data/`；环境 `conda activate` 绝对路径。
4. 训练脚本放 `scripts/`，输出写 `~/mathorcup_runs/<实验ID>/`，日志 + pid + 标记文件。
5. 训练完：`tar.gz` + `sha256` → 下载 → 本地运行 `scripts/check_result.py` 与 R 出图。
6. 结果进 `06_交付/02_结果文件/`，论文进 `06_交付/01_论文/`。
7. 销毁容器，记录本次卡时与实验 ID。

## 9. 一页速查

```bash
# 环境
source /opt/conda/etc/profile.d/conda.sh
conda activate /home/jovyan/conda/envs/<env>
export LD_LIBRARY_PATH="$CONDA_PREFIX/lib:${LD_LIBRARY_PATH:-}"

# 逐卡自检
for i in 0 1 2 3; do CUDA_VISIBLE_DEVICES=$i timeout 60 python -c "import torch;print($i,torch.cuda.is_available())"; done

# 同步代码（DNS 正常）
cd ~/mathorcup && timeout 30 env -u LD_LIBRARY_PATH GIT_TERMINAL_PROMPT=0 git pull --ff-only

# 同步代码（DNS 坏）：本地生成 patch → 上传 → git am
git am --committer-date-is-author-date sync.patch && git rev-parse HEAD

# 后台任务
nohup bash scripts/train.sh > ~/run.log 2>&1 & echo $! > ~/run.pid

# 监控（不要裸 watch）
env -u LD_LIBRARY_PATH /usr/bin/watch -n 15 'tail -n 30 ~/run.log'

# 打包结果
tar -czf ~/results_$(date +%Y%m%d).tar.gz ~/runs/<实验ID>
sha256sum ~/results_*.tar.gz > ~/results.sha256
```
