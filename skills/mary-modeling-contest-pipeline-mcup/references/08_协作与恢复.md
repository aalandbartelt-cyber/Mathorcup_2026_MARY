# 08 双 AI 协作与恢复

## 8.1 角色（三方）

| 角色 | 位置 | 职责 | 不做什么 |
|---|---|---|---|
| Codex | WSL（VS Code Remote-WSL） | **核心工作**：建模推理、模型选型、结果解读、代码/训练/评估、论文 LaTeX | 技术主张的最终负责人 |
| ZCode | Windows 宿主 | 辅助：环境、数据、文档、复核、提交检查、替补 | 能力与 dsh 相近，但不代做 dsh 的评审 |
| dsh（DeepSeek Harness） | Windows | **论文评审与优化**：结构/逻辑/表达/格式/一致性审查 | 不承担建模推理、选型、结果解读 |

原则：**干活的手长在环境里**。Codex 直接操作 `~/mathorcup`；ZCode 通过文件与命令复核；
dsh 的评审意见以 `review` 消息进入协作通道（注明“dsh 评审”），由 Codex/ZCode 落实。

## 8.2 文件信箱（docs/collab/）

| 文件 | 写入者 | 规则 |
|---|---|---|
| `board.md` | 双方各自维护区 | 任务/状态/阻塞/活动日志 |
| `to_codex.md` | 只有 ZCode | Codex 只改状态行 |
| `to_zcode.md` | 只有 Codex | ZCode 只改状态行 |
| `decisions.md` | 双方追加 | 已定事项 D-xxx |
| `handoffs/` | 交接方 | 大任务交接文档 |

消息格式：

```markdown
## MSG-YYYYMMDD-HHMM-xx | 类型 | 状态
- 发起 / 接收 / 时间 / 关联
**标题**
**内容**（背景、要求、约束、文件路径）
**验收**（命令、产物、指标）
**回复**（接收方填）
```

状态：`OPEN → ACK → DONE`；`BLOCKED`（写原因与选项）；`PAUSED`（暂不执行）。

## 8.3 静默模式（默认）

- 只在**任务交接、阻塞、需要决策**时发消息；
- 日常进度只更新 `board.md`；
- 能一句话在对话里说清的，不写文件。

## 8.4 交接包内容

一次交接必须包含：
1. 任务一句话与验收标准；
2. 数据/权重/脚本的**绝对路径**；
3. 可复现命令（含环境名）；
4. 已知坑与不要动的文件；
5. 预计耗时与阻塞点。

## 8.5 阻塞上报

`BLOCKED` 必须写：
- 卡在哪一步、报错原文；
- 已尝试的 2–3 种方案；
- 需要对方做什么（下载/决策/权限）；
- 可选替代方案。

## 8.6 中断恢复

1. `cd ~/mathorcup && git pull --ff-only`；
2. 读 `docs/collab/board.md` 当前状态；
3. 读最近 `DONE` 消息的产物路径；
4. 在干净环境重跑验收命令（训练/推理/校验）；
5. 若产物缺失，从 `_archive/` 或 git 历史恢复；
6. 恢复后更新 board 并提交。

## 8.7 Git 约定

- 开工先 pull；处理完立即 commit + push；
- 提交信息 `collab(MSG-ID): ...` 或 `feat/fix: ...`；
- 冲突时保留双方消息、重新编号，不删对方内容；
- 数据/权重/参考材料不入库。

## 8.8 常见协作事故

| 事故 | 原因 | 防法 |
|---|---|---|
| 两个 AI 改同一文件 | 无写入者约定 | 单一写入者 + 先发消息约定 |
| 版本交错 | 结果目录多版本 | 只留最终版，旧版进 `_archive/` |
| 环境不一致 | 一个用 base、一个用 mathorcup | 命令写全路径或先 activate |
| 路径串项目 | 工作目录是 thruster_project | 每条命令先 `cd ~/mathorcup` |
| 消息丢失 | 只口头说 | 写进 to_xxx.md 并提交 |
